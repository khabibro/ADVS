# ADVS architecture options: evidence and tradeoffs

Date: 2026-09-29. This is an engineering comparison, not a benchmark ranking. Current official capabilities and deployment qualifications are sourced in [research_review.md](research_review.md). All alternatives retain deterministic verification and human review. Final selection belongs in `decision.md` after measured failure analysis.

Options: A = current Paddle plus flat lines and heuristics; B = local OCR with preserved geometry and deterministic extraction; C = local parser with layout/tables and deterministic schema extraction; D = OCR/parser plus constrained semantic fallback; E = cloud Document AI plus deterministic verification; F = VLM-first structured extraction plus deterministic verification.

| Dimension | A | B | C | D | E | F |
|---|---|---|---|---|---|---|
| Korean recognition | Existing explicit Korean model | Same unless separately measured upgrade | Depends on parser recognizer | Depends on recognizer and semantic model | CLOVA/Azure/Google document support; Textract language mismatch | Must measure checkpoint; JSON is not accuracy |

| Table support | None beyond line geometry | Limited summary pairing | Native optional table capability | Native parser plus fallback | Provider-specific cells and merged cells | Often HTML/JSON; exact cells/provenance vary |

The smallest defensible initial change is B for failures caused by ADVS algorithms or discarded geometry. C is a justified experiment if correctly recognized transcript text cannot be associated from existing geometry. D should be added only for demonstrable unresolved semantics and must be optional; it cannot repair lost OCR pixels. E is excluded from this task by the user's no-transfer instruction. F is not selected because there is no measured gain or sufficiently audited provenance on the ADVS sample families.

Do not build every structure preemptively. Preserve page source type, coordinates, original polygons, recognition score, optional detection score, rotation and transform identity now where supplied. Retain line IDs and order. Define table/cell/key-value output as an optional provider capability when selected; do not fabricate it for plain OCR. The canonical field/evidence model, effective-field resolver, workflow configuration, and deterministic verifier remain the stable boundaries.

Decision gates for any later parser/fallback adoption: same dataset and gold/scorer versions; account for every populated field; compare wrong non-null values and required unresolved fields; inspect every wrong output; retain evidence; record model/config/weight hashes; measure CPU/GPU latency and temp/memory use; include negative and ambiguous cases. An increase in extraction recall alone does not justify adoption.
